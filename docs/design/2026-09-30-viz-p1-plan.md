# P1 plan — viewer core (`netstead.viz`)

Status: **done** (#194) · Parent: [network viewer PRD](2026-09-30-network-viewer-prd.md)

> `netstead select-serve` was *not* folded into `netstead viz` as planned below; it
> remains a separate prototype command and is retired by the Workbench (PR #211).

**Goal:** the consistency foundation — one **deck.gl + MapLibre** render path fed by **binary
typed-arrays from the Parquet frames** (no GeoJSON), serving both the full (sub)network and the
selection highlight. Replaces the prototype's MapLibre+GeoJSON rendering.

**In scope (P1):** network links + nodes rendered from binary; hover tooltip (basic attrs);
fit-to-network; selection highlight ported onto this path; `netstead viz <network>` CLI.
**Out (later phases):** layer panel/toggles, attribute styling UI, detail table, diff, multimodal,
GTFS, NL beyond selection, editing.

## Architecture

New submodule `netstead/viz/` (absorbs the `netstead.select` webapp; reuses `netstead.select` resolver):
- `buffers.py` — pure: Parquet link/node frames → packed binary + an index-aligned attrs payload.
- `server.py` — FastAPI: `/` (page), `/api/network.bin`, `/api/network.attrs.json`, `/api/select`.
- `templates/index.html` — MapLibre basemap + deck.gl `MapboxOverlay`; `PathLayer` (links, binary),
  `ScatterplotLayer` (nodes), selection-highlight `PathLayer`, hover tooltip, fit.
- CLI `viz` command (the prototype `select-serve` becomes an alias / folds in).

## Data path (the P1 decision)

Render **true link geometry** (parse WKT `geometry` → flat coords **server-side, once**) via
`PathLayer` binary, preserving the prototype's visual accuracy. Fall back to a **straight
node-to-node** segment when a link has no geometry (zero-parse path, per PRD). Everything the GPU
sees is a typed array; the WKT parse happens once on the server, not per frame, not in the browser.

**Packed binary (`/api/network.bin`, `application/octet-stream`):**
`[uint32 headerLen][header JSON][payload]` where header gives byte offsets/counts and payload is:
`linkPositions: Float32 (flat lon,lat)`, `linkStartIndices: Uint32 (nLinks+1)`,
`linkIds: Float64 (nLinks)`, `nodePositions: Float32`, `nodeIds: Float64`.
JS slices each into a fresh typed array (copy → aligned) and feeds deck.gl:
`PathLayer({ data: { length: nLinks, startIndices, attributes: { getPath: {value: linkPositions, size: 2} } }, ... })`.

**Attrs (`/api/network.attrs.json`):** index-aligned parallel arrays `{link_id[], name[], ref[],
facility_type[]}` for the hover tooltip (not per-feature objects). Detail table (P2) will use a
DuckDB endpoint instead.

**Selection:** `/api/select` (reuse resolver) returns the resolved `link_id`s; the frontend builds
a **highlight `PathLayer`** by slicing the already-loaded `linkPositions`/`startIndices` for those
ids (via a `link_id → index` map) — no second geometry fetch. Gore/merge anchors as a small
`ScatterplotLayer`. This *is* the "selection shares the full-network data path" consistency.

## Verification

- Unit tests (TDD): `buffers.py` — pack → parse round-trips counts/coords; startIndices monotonic;
  straight-segment fallback for a geometry-less link; attrs arrays index-aligned with linkIds.
- Endpoint tests: `/api/network.bin` returns a parseable buffer with expected counts;
  `/api/network.attrs.json` aligned; `/api/select` still resolves.
- Visual (browser): `netstead viz <rdu_i40>` → links render on basemap, hover shows attrs, a NL
  selection highlights the correct path with gore/merge markers. Screenshot.

## Deck.gl loading
Frontend uses deck.gl + maplibre-gl UMD bundles from CDN (no bundler), consistent with the current
no-build page. `deck.MapboxOverlay` interleaves deck layers with the MapLibre basemap.
